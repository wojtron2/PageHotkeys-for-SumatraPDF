# PageHotkeys

Minimal C++/Win32 GUI controller for SumatraPDF page hotkeys.

The program lets you configure global hotkeys in a small Win32 GUI. By default
it uses Raw Input so keys are not consumed by the controller. It then asks
SumatraPDF to run its documented DDE named commands.

It does not use keyboard hooks, synthetic input, overlays, DLL injection,
process scanning, window scanning, or game-specific logic.

SumatraPDF 3.5 or newer is required for DDE named commands such as
`[CmdScrollUp]`.

## Hotkeys

Default enabled hotkeys:

```text
Numpad +  -> CmdScrollDown
Numpad -  -> CmdScrollUp
```

`Scroll lines` controls how many single-line scroll commands PageHotkeys sends
for `Scroll up` and `Scroll down`. The GUI accepts values from `1` to `999`;
the default is `5`.

Next page, previous page, and quit are present in the GUI but unchecked by
default.

Hotkeys can be changed in the app. Each action also has a checkbox that turns
that action on or off without clearing its saved key. Empty hotkey fields still
disable that action. Bare `F13`-`F24` and numpad `+`/`-` keys are accepted;
ordinary keys should use Ctrl, Alt, or Shift.

The global `Consume key` checkbox controls the input backend:

```text
checked    -> RegisterHotKey / WM_HOTKEY, conservative, key is consumed
unchecked  -> Raw Input / WM_INPUT, key is not consumed
```

`Consume key` is unchecked by default. Raw Input mode does not use hooks and
does not send synthetic input, but it is less conservative than `RegisterHotKey`
because the app receives raw keyboard events while it runs in the background.

## Build

```bat
build.bat
```

The script tries MSVC `cl.exe` first, then MinGW `gcc.exe` in C++ mode.
The MinGW path avoids the C++ standard library runtime and links compiler
support statically, so the output is a standalone `.exe`.

Output:

```text
build\PageHotkeys.exe
```

## Run

```bat
build\PageHotkeys.exe
```

Settings are saved to `PageHotkeys.ini` next to the executable.

If the SumatraPDF path is empty, the app checks `SUMATRA_PATH`, common install
locations including `%LOCALAPPDATA%\SumatraPDF`, system `PATH`, and finally
falls back to `SumatraPDF.exe`.

The SumatraPDF field is filled on startup when possible. The `Find in PATH`
button searches system `PATH` for `SumatraPDF.exe` and puts the full resolved
path into the field.

The `Tray` button hides the window to the system tray. Click the tray icon to
show the window again.

The `Info` button opens a small topmost information window. Current version:
`0.1.14`.

For a conservative public build intended for antivirus false-positive testing,
run `build-public.bat`. It creates `build_public\PageHotkeys.exe` without Raw
Input, without direct DDE imports, and without the `Consume key` option. That
variant uses `RegisterHotKey` and runs `SumatraPDF.exe -dde "[Cmd...]"`, so
configured keys are consumed by Windows.

For the private Raspberry Pi controller build, run `build-with-rpi.bat`. It
creates `build_rpi\PageHotkeys.exe` with an extra UDP controller section. That
code is guarded by `PAGEHOTKEYS_RPI_UDP` and is not compiled into the normal or
public builds.

The RPi build accepts UDP packets on the configured port. With the default
token, the packet format is:

```text
wojtron UP
wojtron DOWN
wojtron PREV
wojtron NEXT
```

If the token field is empty, the RPi build accepts `UP`, `DOWN`, `PREV`, and
`NEXT` directly.

## Design

The intended flow is:

```text
Keyboard
  -> Windows
  -> RegisterHotKey() / WM_HOTKEY
     or Raw Input / WM_INPUT when Consume key is unchecked
  -> PageHotkeys.exe
  -> DDE server SUMATRA / topic control
  -> SumatraPDF page/scroll command
```

No PageUp/PageDown key events are generated by this program.
